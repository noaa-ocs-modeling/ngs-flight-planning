## 🔧 Documentation Standards

### Writing Guidelines
- Use clear, concise language
- Include code examples where appropriate
- Add diagrams for complex workflows
- Keep documents up-to-date with code changes
- Follow [Markdown style guide](https://www.markdownguide.org/basic-syntax/)

### Naming Conventions
- Reports: `REPORT_NAME.md` (uppercase)
- Guides: `guide-name.md` (lowercase with hyphens)
- API docs: `module_name.md` (underscore-separated)

### Version Control
- All documentation tracked in git
- Update CHANGELOG.md for significant doc changes
- Tag documentation versions alongside code releases

## 📝 Contributing to Documentation

### How to Contribute
1. Check existing issues for documentation tasks
2. Create a new issue if needed (label: `documentation`)
3. Fork the repository and create a branch
4. Write/update documentation following standards above
5. Submit a pull request with clear description
6. Address review feedback

### Documentation Review Process
- All documentation PRs require at least one review
- Technical content reviewed by domain experts
- Writing style reviewed by technical writers
- Merge only after all checks pass
